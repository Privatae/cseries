# lane) that get longer than the 180 s every other gate gets. Read by BOTH
# scripts/pre_merge_gates.sh and scripts/smoke_test.sh, so the two runners
# cannot disagree.

# One line per gate: "<gate file> <seconds>". Add one only with a measurement,
# written above it; never to quiet a hang.

# tests/ is the pytest lane at the end of pre_merge_gates.sh, which reads this

# The grok command matrix runs 16
# rows x 3 variants, each row in its own process with busy children (about a
# third of a core each, so the activity floors are crossed). Its own work is
# CPU, so it is over the 180 s default by construction, not by load. The limit
# pre_merge_gates.sh applies is hang_watch's --cpu-budget: CPU seconds of the
# gate's whole process tree, not wall time. Measured on the build machine under
# hang_watch --log: 197 s of CPU, 269 s wall; 214 s of CPU,
# 269 s wall (load average about 2 on 8 cores). 600 s is 2.8 times the
# higher reading.
test_harness_grok_command_matrix.py 600

# Part M runs the Telegram connector in real containers

# the gate never approaches; smoke_test.sh reads it as wall seconds, where the
