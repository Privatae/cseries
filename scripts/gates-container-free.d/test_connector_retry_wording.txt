# A connector (system-apps telegram, slack, discord) words a failure it is about to try again so neither of the app proof's readers (tools._LOG_ERROR_RE, app_verify._ERROR_RE) takes the line for an error, and still says why in plain words; a failure it gives up on (a message dropped, a reply let go) still reads as one. Each connector.py is loaded as a module and every retried path (the poll / Socket Mode / gateway loop, a part's send, Slack's picture upload, a message the Host answers 503) is fed the failure as the standard library raises it: refused, broken pipe, reset, closed with no answer, cut short, timed out, a name not resolved, real TLS failures, a handshake answered 500, the platform's 5xx with no JSON, every errno and getaddrinfo failure; plus the kernel's 502 detail for a platform call that did not go through, made by a real refused connection through authz._do_http_call and nac_connector.platform_call on both broker lanes. No network past loopback, no database, no container.
