# The claude-code harness closes the idle-window gap that a CLI's closed provider connection opens, with the same rule as harness_core. A reading counts as on the network if it, or one within the last idle window, saw a connection, so a run that has just answered its model is not stopped as "never started" when the watchdog reads the tree before the SDK reader handles the reply; the activity clock is never reset, so a silent tree is still stopped one idle window after the close and a flapping connection is still bounded by the model-wait window, with or without a tool open. The tree readings and the clock the watchdog reads are scripted and the stand-in SDK hands over its reply only after the first closed reading was judged: nothing waits on machine speed. Real run_stream handler, stand-in SDK; no CLI, no pod.
