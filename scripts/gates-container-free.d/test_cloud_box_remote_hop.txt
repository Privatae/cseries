# 2026-10-27 (C-Series Cloud: remote access on the cloud image): the hop between the Host and its remote-access door on a cloud box, with door.nft and remote.nft both loaded, in private namespaces playing the box, the Host, the door and an app container on bridges built as podman builds them. With the bridges' frames out of the IP hooks (a box's state): the tunnel reaches the door's 8443 and the door the Host's 8800, data both ways, the door reaches no other Host port, and an app reaches the Host's 8800. With bridge-nf-call-iptables on, where the kernel has br_netfilter: door.nft's private-range rule drops the tunnel, the door-to-Host and the Host-to-app hops alike (measured), and after the box's own `cseries-firewall bridge-off` (the step `load` runs right after door.nft) all three are open again, the door still reaching no other Host port. Text: the box's modprobe.d refuses br_netfilter (install br_netfilter /bin/false), and load runs bridge_off right after door.nft. Needs nft, ip, unshare and root or a user namespace of its own.
