# 2026-10-19 (C-Series Cloud box): the box's updater takes only a release signed for kind cseries-cloud with the pinned release keys (verify.js's, a vector shared with release-sign, and bootstrap.sh's embedded verifier agreeing), refuses unsigned, tampered, wrong-key, wrong-kind, older and same-version manifests and an overlay that does not match or holds a link, rolls a failing image back to the previous overlay and images (a fake cseries-guest), and rolls back a release whose Host answers its web port but is not ready by the deep health check (cseries-guest ready, checked against a fake curl), and the release workflow's cloud-release.json is one the box accepts. No network, no container. 2026-10-25: a release that changes the unlock agent's program or the box's library restarts the running agent; one that changes neither leaves it. Self-update first: after the unpack and before any install the release's own updater is handed the tree (same interpreter, -I, the same arguments and --handed-over); it verifies the manifest again and reuses the unpacked tree; a tree without an updater, or one the exec cannot start, leaves this one to install; the updater loads the library beside its own script. Run as processes with a real exec: a broken release updater leaves the old release in place with nothing installed, and the release's updater, started with --handed-over, installs it without handing over again. In-process otherwise.
