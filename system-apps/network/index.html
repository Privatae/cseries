Bastions

Your secure doors into your private network. Each bastion is a machine you stand up that joins your mesh — enrolled once, then it talks to your network directly. Shut a door any time. A networked machine you anchored waits for your approval before any other Host gets lanes on it — pending pairings show on the card with Approve (asks for your code) and Deny; Revoke removes an admitted host at once. Each card also lists the other Hosts the machine says it serves: message one you are connected with, or send a connection request.

Pairing a machine on another network?

Give that machine's public address, as a site that shows your IP address reports it on that machine. Its line then pairs from there, and this Host's pairing port opens to that address only.

Egress — what your Host reaches

Your Host reaches the internet through your own bastions, over your own connections — you decide what it can reach, host-local, and you sign those rules. The platform meters throughput only; it never sees where your Host goes. (Set limits from your agent — this is a read-only view.)

Network access control

Two layers, opposite defaults. Egress (your reach outward) is open by default — you opt in to limit it. Management (operating servers in your mesh) is denied by default — no management operation your Host sends there runs without a grant. Posture decides what each bastion is trusted to do.

Anything that widens your reach — an allow, a grant — asks for your authenticator code. Tightening is free.

Lanes

Three lanes, each opened on its own. Ingress (who reaches in) admits the machines you have paired until a rule says otherwise; Management (operating your mesh) is denied by default; Egress (your reach outward) is open by default. Pending drafts pin to the top of their lane and the lane opens itself.

Inbound policy — rules match a bastion's fingerprint, classification, or posture and assign an enforcement profile: allow grants its permits, quarantine denies. Approving an allow profile widens reach (asks for your code); a quarantine is free. Removing an approved rule that keeps machines out — a quarantine, or an allow that admits nothing — can let them back in, so it asks for your code too.

Agents

AI/agent activity your bastions observe on the machines they run on — what's running and whether it's talking to a model. This is visibility: detection is soft and evadable, never the wall. The wall is your host-local NAC. Here you reconcile — sanction what you asked for, contain what you didn't.

Agents

Reported by your bastions each check-in. Unrequested = carries no delegation tag you issued — “agent activity you didn't request.” Each card says how the agent was started (a terminal, a remote session, a scheduler, a service, another agent) and opens to the bastion's evidence, one typed line per signal. Contain terminates an agent and every process it started.

Scheduled — jobs that would run an agent

Crontabs, timers, launchd jobs and scheduled tasks on your machines whose command runs an agent or an automation. Listed before they fire — the “ran every night for months and nobody knew” shape, caught from the schedule.

Automations — no model

Browser drivers, input injectors, RPA runtimes: things that drive the machine with no model behind them. Inventory, not an alert. The moment one starts talking to a model it is an agent and moves up.

Apps using a model

Software you're running that talks to a model — a desktop chat app, an IDE, a browser tab. Shown so you know what's talking to what; never alerted on, never contained.

Delegation tags — what you've sanctioned

Launch an agent with a tag's PRIVATAE_AGENT_TOKEN and it reads as requested. Soft, expiring, revocable — it sorts sanctioned from casual; it isn't the wall.

Bastion agents

A bastion agent is a small program your bastion runs on your own machine for a folder you granted with search: it indexes the folder there, redacts personal data before anything leaves, and answers your host's searches. Your files never move. The bastion installs and updates it from the grant — nothing to configure. If a machine is missing something (Python, openssl), it says so here.

Servers on your machines

A server a host built for you — a private code server, say — runs on your own machine with no network: it cannot reach your machines, your network or the internet. The only way in is a host's tunnel, and only for a host you let in here: each host needs its own reach grant for each server, and you approve it. Revoking one takes effect at once.

Per-peer rules

Each rule names one sender, by handle or address, and lets what it sends into your inbox or keeps it out, whatever the setting above says. A rule does not stop messages from a Host you gave a permission slip: block that Host in Circles. Connection requests always reach you.
