# gates-store-apps.txt — the gates whose subject is a STORE app, and which app.
#
# Store apps are not kernel code, so their gates run separately.
# A CI run once took 19 min: test_connector_telegram_example.py,
# a 9-minute gate of the Telegram store app, was picked as covering a kernel
# change, failed in the pool and ran 9 minutes more alone. A store app reaches a
# Host when a person installs it (or the store updates it), on its own publish,
# not with the image, so its gates run on its own lane:
#   - scripts/store_app_gates.sh runs them (--changed-from <ref>, --app <id>,
#     --all), with pre_merge_gates.sh's pool, per-gate limits and hang_watch;
#   - the store-apps job of the forge's .gitea/workflows/check.yml, beside the
#     gates job, runs the ones whose app a pull request changed
#     (`--changed-from`). GitHub's .github/workflows/test.yml runs none of
#     them: its pytest leaves out every tests/ entry here, as
#     pre_merge_gates.sh does;
#   - the store-lane publish of an app runs `--app <id>` first, and a red run
#     stops that app's publish only.
# pre_merge_gates.sh (the PR run and the ship's full run) and smoke_test.sh's
# container-free pass never run a gate listed here. scripts/test_gate_coverage.py
# counts a line here as the gate's registration and refuses a gate that is also
# in gates-container-free.d/, gates-infra-only.d/ or invoked by smoke.
#
# A store app: a system-apps/<id> that is not in scripts/image_baked_apps.txt and
# whose catalog row (app_store_apps) is distribution 'store' and not is_default,
# i.e. one a person chooses to install. Kept in the kernel lane, with why:
#   app-store, publisher  is_default: every new Host installs them at first boot
#   claude-code, claude-code-harness, _harness_runtime  the coding-harness
#                         plumbing (claude-code's row is distribution 'harness';
#                         the other two have no store row)
#   security, terminal    no store row; not installable from the store
#   _template             the scaffold for new apps, not an app
# A gate that tests kernel code with a store app as its fixture stays in the
# kernel lane (test_app_origin.py uses backups; test_browser_profile.py tests
# server/applications/browser_profile.py; test_connector_platform_inflight.py
# tests server/routes/connector.py; test_connector_retry_wording.py also drives
# the kernel's authz._do_http_call and nac_connector.platform_call).
#
# One gate per line:  <gate> <app-id>[,<app-id>...] [<path>...]
#   <gate>   a scripts/ file name, or a tests/ path (the kernel lane's pytest
#            run then leaves that file out)
#   <path>   more source the gate's subject lives in, outside system-apps/<id>/;
#            a path ending in / is a directory. A change there, to
#            system-apps/<id>/ or to the gate file selects the gate.
# '#' starts a comment.
