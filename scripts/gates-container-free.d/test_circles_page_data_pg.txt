# Circles' page data against a real kernel schema. v219 applies on the schema before it (the marks table, its CHECKs and the thread list's four indexes), a second run changes nothing, and a fresh Host's init-db.sql declares the same table, constraints and indexes. PUT /api/circles/thread/{kind}/{id}/seen only moves the mark forward (of two PUTs at once, the one that began first and wrote last never moves it back), keeps a watched turn's token on your Host's pages only (the last 32), takes 'original' and the old 'self', refuses a deleted thread, another entity's thread and a bad id, and keys a person's mark by the reading operator. GET /api/circles/threads: a reply watched to its end never lights its page; a reply of an unwatched turn, a scheduled task's report (the runner's writer) and an agent's result do, on a thread and on the original conversation; the person's own words, a split marker, a wake-up's hidden reply and another thread's rows never do; counts stay the transcript's, the rows the list reads are shown_where's, and waiting_on_you is GET /api/tickets?status=open&asked_in='s count for every page. GET /api/circles/thread/self/{id}/page carries thread_state_parts, running_spend (uncounted and unpriced turns kept apart, another thread's never counted), the list's marks and totals_vs_transcript (pinned: a superseded row, a wake-up's hidden row and an untagged row on the original conversation); other kinds are refused; it needs read:inference_log. GET /api/circles/conversations sends unread and unread_count for peer Hosts, people (per operator) and rooms (through the bridge); a room the bridge does not answer for, is slow for, or whose page cannot be counted says unread_unknown with unread_count null, within circles_marks.ROOM_UNREAD_DEADLINE, and never holds or breaks the list. POST /api/circles/nudge passes client_id to push_nudge. Fresh clone of the kernel schema on TEST_PG_DSN / PEER_TEST_DSN / TEST_DSN, else a docker throwaway. Measured on the build machine: 102 checks, about 40 s wall.
