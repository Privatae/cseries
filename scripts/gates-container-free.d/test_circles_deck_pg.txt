# Circles' deck against a real kernel schema. GET /api/circles/conversations pairs each person with the Host on their contact (host_entity_id, host_contact, host_blocked, contact_id) and each peer Host with the people on the same list; one Host on two people, a person with no host contact, a person with no Host recorded; a blocked person and the Host blocked through them never listed, a Host blocked directly left out while its person stays marked; contacts.blocked_sets held to contacts.block_refuses for every Host and person seeded; groups from roster.list_groups for a read:group caller, null without. Two operators of one Host see only their own conversations, and a knock addressed to one is never at the other's door. GET /api/circles/door lists each of the five kinds once (a Host's and a person's request, a group knock, an introduction, a machine request, a Host found on your machine) and never a blocked sender's card, a found Host already held, a dormant or unresolved peering, an archived card or an ordinary notice; every item's own Accept and Not now, sent through the real routes, takes it off the door; it needs read:inbox, read:topology and read:group. GET /api/circles/waiting lists every open decision with its room (thread, original, project, none), each agreeing with GET /api/tickets?asked_in= and the thread list's waiting_on_you, the support drafts waiting for Send, and the door's count; it needs read:tickets. Speed at 300 people on 100 Hosts printed. Fresh clone of the kernel schema on TEST_PG_DSN / PEER_TEST_DSN / TEST_DSN, else a docker throwaway. Measured on the build machine: 70 checks, about 15 s wall.
