Skills shows the steps your Host follows for each kind of job. Some skills come with every Host. Others your Host writes for itself, and those you can read, edit, retire or bring back. It comes with every Host.

## What is a skill?

A short written procedure for one kind of job: when to use it, the steps, how to check the result, and what to do when it fails. Your Host reads it and follows it with what it already has: its tools, your installed apps, your connections and your machines.

## Can a skill run code or give my Host new permissions?

No. A skill is written steps, not a program: it can hold a short example, never a whole program. Anything that needs a program is an app your Host installs from the App Store, and the skill says to install it. A skill grants nothing either: everything it leads to still goes through the same approvals as any other request.

## Can my Host write its own skills?

Yes. When a job has steps worth keeping, your Host writes a skill for it. Every skill it writes is checked against one standard before it is saved. It must have the four parts above, keep its steps short enough to be read in one piece, and say what it was written from. It lists the tools it uses, and every tool its text mentions must be on that list, so the list always tells you what the skill touches. A skill that carries a password or key, tries to pull in more instructions from somewhere else, hides text you cannot see, or contains text aimed at steering an AI is refused. A refused skill is not saved, and your Host is told every rule it broke.

Your Host can keep improving a skill that one of your turn types uses without asking you again. Each change is a new version you can see here. A skill is checked again each time a turn type uses it. If it no longer meets the standard, or is gone, your Host is told which skill and why on that turn and works without it.

When a message you send uses every word of the name of one of your Host's own skills, or closely matches what the skill is for, that turn shows your Host one line about the skill: its name, what it is for and how to open it, never its steps. At most two skills are shown this way on a turn, and only ones your Host or you wrote. A turn type limited to some projects, to less of your Host's memory, or to tools that cannot read a skill is shown none.

## Can I edit or undo a skill my Host wrote?

Yes. Every change is kept as a new version, so nothing is lost. For each of your Host's own skills you can:

- see every version, who wrote it (your Host or you) and what changed;
- edit it yourself, checked against the same standard;
- retire it, so no job uses it, with its history kept. A skill one of your turn types uses can't be retired while that type uses it: first the type moves to a different skill or is retired, which you approve;
- restore any earlier version, which is checked again first.

A skill your Host wrote for an MCP server it is connected to is marked stale when that server's list of tools changes, until your Host revises it.

A skill your Host wrote while its turn had read something from outside (a web page, another Host's message, an agent's report, an MCP tool's answer, a file you uploaded) is marked review. Until you review it, every turn that reads it is treated the same as a turn that read that outside content, and it is never shown to a turn as one of the matching skills above. Your Host can still find it when it searches. Read it, then edit and save it, changed or not, to clear the mark. Restoring a marked version brings its mark back with it.

You can also write a new skill yourself with New skill. It is checked against the same standard and kept with your Host's own skills.

The skills that come with your Host can be read here but not changed.
